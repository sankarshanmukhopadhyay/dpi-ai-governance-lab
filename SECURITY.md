# Security Policy

## Supported versions

Security and governance-integrity fixes are applied to current `main` and the latest supported release identified by repository status/release metadata. Older versions should be treated as unsupported unless a maintainer explicitly states otherwise.

## Reporting a vulnerability

Do **not** open a public GitHub issue for an undisclosed vulnerability. Use GitHub private vulnerability reporting when available, or contact the repository maintainer through a private channel identified on the maintainer profile.

Do not use placeholder or unverified security contact addresses.

Include the affected revision/version, reproduction steps, impact, affected experiment/evidence artifacts, and any known mitigation.

## Governance and evidence implications

This repository is an experimental governance lab. A defect in an experiment, control implementation, evidence transform, publication pipeline, or governance model can invalidate prior experiment evidence. Remediation must identify affected evidence and must not convert missing, stale, or contradictory evidence into PASS.

The lab owns experiment execution and evidence capture for its declared cases. It does not acquire regulatory, institutional, or upstream normative authority merely by modelling or testing it.
